The marks of work nobody finished.

anti-slop is a plugin for Claude Code. It reads the interface you already have and reports what was left at its default — the palette nobody picked, the empty state nobody wrote, the dark theme nobody opened — as a ranked list with a file and a line.

Forty-nine of those marks, across five axes. You do not need the vocabulary to act on the report. 

$ git clone https://github.com/luantaraschi/anti-slop
> /plugin marketplace add ./anti-slop
> /plugin install anti-slop@anti-slop

It has no list of banned patterns

Forbid the purple gradient and the generic reappears wherever the list does not reach. A finding here is two things at once: the pattern is present, and there is no evidence anyone chose it. Neither half alone is a finding.

So the auditor looks for the choosing first — a variables file, a :root block, a theme config, a comment sitting beside the value it governs. Where it finds one, the pattern is somebody's decision and the report says nothing about it.

Two landing pages. Only one was decided.

Both are specimens in this repository. On the left, the palette, the icon, the headline and the three identical cards are all whatever the scaffold produced. On the right, every value was answered for before any code and carries its reasoning beside it — and then somebody composed the page, which is a separate job the build skill says outright it does not do.

What a run gives you back

A verdict in plain words, then a ranked list. ROOT holds the findings that close others when you fix them; THEN holds the rest. One row, one id, one place to open.

Five real findings, each checked against fixtures/slop-dashboard on 2026-08-18. The two under ROOT are there because the same evidence produces four more: the empty theme is also why A3 and A5 fire, and the retyped card is also why A4 and A6 do. Two files close six findings. Twenty-one blind reports are committed under calibration/, written by agents that were given the skill and the directory and nothing else.

Two skills, and they are one loop

anti-slop:audit

Reads what already exists. Run it on the whole project or on one file, and on all five axes or on one of them. It reads any web stack: 39 of the 49 tells never name a framework, a build tool or a library.

anti-slop:build

Runs before the components exist. It makes you answer four things the auditor cannot answer for you — what the product concretely is, how it talks, how sober it should look, how much belongs on one screen — and writes every value it derives with the reasoning beside it, in the places the auditor searches for evidence.

Which is how each half tests the other: a tell that fires on a tree the build skill produced is the build skill's failure, and it arrives with a file and a line.

The claim it does not make. Nothing in this catalog proves a model wrote the code. It fires on absence and repetition, which look the same whether a person typed every line or an agent did. The report never says a file was AI-generated.

What is not finished. 21 of the 49 tells have never been tested against a case they must not fire on, and the validator prints that number every time it runs rather than hiding it.
